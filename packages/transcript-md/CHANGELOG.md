# Changelog

## 0.2.0 (2026-10-20)

Every transcript.md now names the standard it follows. `STANDARD` (`https://hypercontext.wiki/standards/conversation`) is exported and the schema accepts `standard` with that one value. `validateConversation` reports a header without it, or with another value, as `self-doc:missing` at level error, and `transcript-md validate` exits 2 on it; readers, sharing checks, citations and the Python companion report it and keep reading. `createConversation`, `annotateConversation` and `reviseConversation` stamp it directly after `kind`, and the shared transaction refuses to write a record without it. New `transcript-md stamp-standard [--workspace DIR | --transcripts-dir DIR] [--apply] [--json]` backfills existing records under the mutation lock, byte-preserving and idempotent, skipping unparseable headers, redirects, incomplete journals and versions something cites; `stampStandard` and `stampPlan` are the pure edit. Also exported: `SELF_DOC_MISSING`, `blockingDiagnostics`, `withStandard`, `stampConversationStandards`.

The standard link names its version. `STANDARD` is `https://hypercontext.wiki/standards/conversation/v1` and every writer stamps it; the schema accepts it and the bare unversioned URL, so records stamped before versions keep parsing. `validateConversation` reports the bare URL as `self-doc:missing` (it predates versions; `stamp-standard --apply` upgrades it in place, under the same lock and hash guards, byte-preserving and idempotent), and a `/v<N>` this package does not implement as the new `self-doc:version` (error). A wrong `standard` value is now only a self-documentation finding, no longer also a blocking `SCHEMA_INVALID`. Readers, sharing, citations and the Python companion treat both codes as non-blocking; `validate` exits 2 on both; writers upgrade the bare URL and refuse to downgrade a future version, and `stamp-standard` skips one as `self-doc:version`. The package ships the standard's manifest at `standards/conversation/v1.json` (exported as `MANIFEST` and as `./standards/conversation/v1.json`), whose `codes` list every code `transcript-md validate` can report: the header codec's, the reader's body, turn, redirect and enumeration codes, the legacy reader's, and `INVALID_ARGUMENTS`. Those 92 codes are gathered into one table, `DIAGNOSTIC_CODES`, from which the codec, the reader and the legacy reader take every diagnostic's level; an unlisted code throws. `validate` reports a system error as `READ_INCOMPLETE` instead of an errno such as `ENOENT`. A test proves manifest, table and sources agree. The schema gains the two optional keys Supersuit already writes, defined exactly as Supersuit's copy defines them: `setting` (`in-person`, `remote`, `hybrid` or `unknown`) and `on_behalf_of` (an array of non-empty strings); records carrying them were reported as `UNKNOWN_KEY`. The manifest's `header.keys` now carries each top-level type, const, enum and array item type the schema declares. Also exported: `STANDARD_UNVERSIONED`, `SELF_DOC_VERSION`, `SELF_DOC_CODES`, `standardFinding`, `conversationDiagnostic`, `diagnosticLevel`.
